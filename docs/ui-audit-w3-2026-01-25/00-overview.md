# 00) 개요/방향 (W3 범위)

## 범위 정의

- “3주차까지 개발된 화면”을 **실제 구현된 라우트 중심**으로 점검했습니다.
- 아직 미구현/불완전한 기능은 “지금 당장 해커톤 데모에서 임팩트를 줄 수 있는 연출/표현” 관점으로 **UI가 견딜 수 있는 실패/로딩/더미 상태 디자인**까지 포함했습니다.

## 데모 임팩트를 위한 “한 줄 방향”

현재의 핑크 톤/라운드 UI를 유지하되, “예쁜 SaaS”에서 멈추지 않고 **“시네마틱 제작 스튜디오”** 느낌으로:

- **콘트라스트를 크게** (더 어두운 베이스 + 더 밝은 하이라이트) 해서 “프로 장비/편집툴” 인상을 주기
- 텍스트 위계(타이포)와 정보 밀도를 정리해서 **작업 흐름이 더 ‘빠르게’ 읽히게**
- “AI가 생성 중/완료” 같은 순간에 **연출(모션/사운드/빛)** 을 넣어 **데모에서 한 번에 이해되는 장면** 만들기

## 이번 라운드 전제(사용자 결정 반영)

- 랜딩/앱 전반은 **한국어 올인**(영문 혼용 최소화)
- 전환 구현은 **제약 없음**(필요 시 View Transition API 포함 가능)
- AI 연동 실패/미완성은 “개발 진행 중”으로 보고, 이번 문서는 **전반적 디자인 개선**에 집중

## 컨셉/모드 기반 피드백(선택형)

이번 문서는 “딱 1가지 톤”으로 밀어붙이기보다, 사용자가 선택할 수 있는 모드로 나눠 제안합니다.

- A) **Bright Studio(라이트, 기본)**: 밝고 친근하지만 “편집툴/스튜디오” 문법(16:9/타임코드/트랙/큐)을 강화
- B) **Studio Mode(다크, 선택)**: 짙은 네이비/차콜 + 네온 하이라이트 같은 무드는 이 모드로 제공

자세한 가이드는 `11-concepts.md` 참고.

## 우선순위 (해커톤 기준)

### P0 (데모 체감이 바로 바뀜)

- 라우트 전환/모달/탭 전환에 **일관된 모션 시스템** 적용 (08 문서 참고)
- 프로젝트 상세(Story/Scenes)에서 **“다음 해야 할 일”을 1개만 강하게** (Primary CTA)
- 씬 편집(노드 캔버스)에서 상태(준비/진행/완료/실패)가 **색/형태/모션으로 즉시 구분**

### P1 (완성도/신뢰감)

- 빈 상태(Empty) 디자인을 “허전함”이 아니라 “온보딩”으로 전환
- 실패 상태(예: 프롬프트 생성 실패)를 “막힘”이 아니라 “대체 경로 제공”으로 전환

### P2 (시간 남을 때)

- 마이크/비디오/채팅 같은 협업 UI를 “플로팅 바” 하나로 더 정교하게(상태/권한/연결 품질)

## 발견된 데모 리스크(기능) 메모

디자인 범위는 아니지만 “화면 상태(성공/실패)” 확보를 위해 확인된 이슈입니다.

- 마스터 프롬프트 생성이 로컬에서 실패하며 UI는 “프롬프트 생성에 실패했습니다”로 떨어짐
  - FE: `itda-frontend/src/components/scene-editor/panels/MasterImagePanel.vue:82`
  - BE: `POST /api/ai/prompts/generate`가 Vertex 연동 실패 시 5xx로 떨어질 가능성
- 씬 편집에서 “그리드 추가” 등 일부 액션이 API 에러로 인해 정상 플로우(노드 확장)까지 이어지지 않음(로컬 재현)
  - 결과적으로 W3의 핵심(마스터→그리드→샷→영상) 성공 상태 화면을 UI로 만들기 어렵고, 실패/빈 상태만 노출될 위험

이 리포트는 위 리스크를 전제로, **성공 상태가 없어도 데모에서 ‘그럴듯하게’ 보이도록**(스켈레톤/목업/가짜 미리보기/상태 배지/모션 연출) 제안을 포함합니다.
