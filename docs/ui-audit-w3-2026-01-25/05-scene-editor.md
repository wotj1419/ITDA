## 현재 관찰

- “노드 기반 제작 흐름”이 제품의 핵심이고, 지금 UI는 그 골격이 이미 있음(강점).
- 다만 데모 관점에서는 아래가 가장 크게 체감됨:
  - 노드/사이드바/플로팅 바가 동시에 존재해서 **시선이 분산**
  - 상태(준비/실패/진행) 표현이 약해 “AI 작업툴” 느낌이 덜함
  - 일부 액션은 로컬에서 에러로 떨어져(프롬프트 생성 실패, 그리드 추가 실패) **성공 상태 화면 연출이 어려움**

## 뷰포트(데스크톱)로 보니 더 뚜렷한 점 (1440x900 기준)

- 캔버스 중앙에 노드가 “크게 떠 있고”, 주변이 비어 보여서 **제작 툴의 밀도**가 부족하게 느껴짐.
- 우측 패널이 열리면 괜찮아지지만, 패널이 닫힌 순간에는 “작업 중” 느낌이 약함.
- 즉, 좁은 화면에서의 문제(답답함)보다 넓은 화면에서 **패널 구조/정보 밀도 부족**이 더 큼.

## 디자인 개선 제안 (핵심)

### 0) 16:9 “모니터”를 제작 화면의 기준으로

요구사항이 “AI 영화(스토리)”보다 “AI 영상 제작 스튜디오(편집툴)”에 가까우면,
씬 편집은 캔버스만으로 끝나면 안 되고 **Preview Monitor(16:9)** 가 상단/우측에 항상 보이는 구조가 더 어울림.

추가로, 제작 화면(씬 편집/타임라인)은 상단바에 **Studio Mode 토글(다크 전환)** 을 제공하면 “프로툴” 인상이 크게 올라감.

#### 모드별로 무엇을 다르게 할까?

- Bright Studio(라이트, 기본)
  - 캔버스/노드 배경은 밝게 유지하되, “툴” 메타(타임코드/해상도/상태)를 또렷하게
  - 글로우/네온은 최소(선택 상태 1곳만)
- Studio Mode(다크, 선택)
  - 캔버스 배경을 잉크 톤으로 내려 “모니터/패널” 대비를 올림
  - 네온 하이라이트(핑크/코랄)는 **포커스/선택/완료 순간**에만 사용

### 1) “캔버스만” 주인공이 아니라, “모니터 + 캔버스” 2축이어야 함

- 영상 제작 스튜디오 인상을 주려면 “결과(프리뷰 모니터)”가 항상 같이 살아야 함.
- 추천 우선순위(제작 화면 기준):
  1) Preview Monitor(16:9)
  2) 캔버스(노드)
  3) 인스펙터/설정 패널(선택 노드)
  4) Render Queue/Job Status
  5) 미니 타임라인(확정 클립) / 협업 바

구체적 개선:

- 우측 패널이 열리면 캔버스 배경을 살짝 어둡게(또는 블러) 해서 “설정 편집 모드”로 전환
- 선택된 노드에는 “글로우 링” 1개만(과한 테두리 중첩 금지)
- 모니터에는 항상 “현재 선택 노드의 결과(또는 플레이스홀더)”를 연결해서, 사용자가 ‘지금 무엇을 만들고 있는지’가 즉시 보이게

### 2) 노드 디자인을 “유리 카드”에서 “스튜디오 장비”로

현재 라운드 핑크 테두리는 귀엽지만, 제작툴/편집툴의 단단함이 약함.

- 노드 배경: 더 어두운 표면 + 얕은 유리 느낌(blur는 최소)
- 상태 표현: 색만이 아니라 형태(예: 좌상단 LED 점, 진행 바, 실패 시 경고 아이콘)
  - `PENDING`: 회색/점선 테두리 + “준비” 텍스트
  - `RUNNING`: 얇은 “스캔 라인” 애니메이션 + 진행 스피너
  - `SUCCEEDED`: 썸네일 + 체크 + “완료”
  - `FAILED`: 빨간 배지 + “재시도” CTA를 노드 내부에

### 3) “마스터 이미지 생성” 패널은 스텝형이 더 적합

현재 라디오/체크가 한 화면에 몰려 있음.

- Stepper로 분리:
  1) 스타일(프리셋 카드)
  2) 시간대/분위기(2개 토글)
  3) 오브젝트(선택 칩)
  4) 프롬프트(미리보기 + 수정)
- 마지막에 “이미지 생성” 버튼 하나만 강하게.

### 4) 실패 상태는 “대체 경로”를 포함해야 함 (데모 생존)

현재는 “프롬프트 생성 실패” 텍스트만 보여서 막히는 느낌이 큼.

- 실패 시 바로 제공할 것:
  - “직접 프롬프트 입력(텍스트 박스)” 폴백
  - “샘플 프롬프트 적용” 버튼 2~3개(스타일별)
  - “다시 시도”는 Secondary

참고 위치:

- FE: `itda-frontend/src/components/scene-editor/panels/MasterImagePanel.vue:82` (프롬프트 생성 실패 메시지)

## 전환/모션 제안 (씬 편집에서 가장 중요)

### 1) 노드 생성/연결

- 노드 추가 시:
  - 노드가 “팝” 하고 생기기보다 **캔버스에서 밀려 나오는** 느낌(translate + scale)
  - 엣지(연결선)는 그려지는 애니메이션(선이 0→100%로 그려짐)

### 2) 노드 선택 ↔ 우측 패널

- 클릭한 노드의 썸네일/제목이 우측 패널 헤더로 “이동”하는 공유 요소 전환 권장
  - Chrome 데모라면 `View Transition API`로 빠르게 임팩트 가능
  - 폴백은 `transition: transform/opacity`로

### 3) AI 작업 상태 변화

- `RUNNING → SUCCEEDED` 순간은 데모에서 “와…”가 나오는 지점:
  - 썸네일이 서서히 나타나며(blur→sharp) 체크가 찍히는 300~450ms 연출
  - 실패는 흔들림(shake)보다 **짧은 붉은 플래시 + 재시도 버튼**이 더 성숙함

## 데모용 “연출” 아이디어 (기능이 아직 불안정해도 가능)

- “가짜 결과”라도 썸네일/클립이 뜨는 듯한 스켈레톤/플레이스홀더를 더 세련되게 만들면,
  - 실제 AI 연동이 완벽하지 않아도 “완성된 툴” 인상을 남길 수 있음
- 예: 노드 썸네일 자리에
  - 필름 프레임 + 로딩 그레인 애니메이션
  - “Rendering…” 타임코드(00:00:03) 카운트업

## 데스크톱 레이아웃 제안(>=1280px)

1440px 이상에서는 “여백을 줄이는” 게 아니라 **스튜디오 패널을 추가**해서 밀도를 만드는 게 정답.

### 추천 3패널(기본)

- Center(메인): 캔버스(노드)
- Right(인스펙터, sticky):
  - 선택 노드 설정(현재 패널)
  - Render Queue/Job Status(대기/진행/완료/실패)
- Top-right 또는 Right 상단: Preview Monitor(16:9)
  - 실제 영상이 없으면 썸네일/더미 영상 + 타임코드/해상도 배지로 “모니터” 느낌 유지

### 선택형 레이아웃 토글(사용자 선택)

- `Focus: Canvas` / `Focus: Monitor`
  - Canvas: 모니터를 작게(PiP)
  - Monitor: 모니터를 크게(편집툴 감성 강화), 캔버스는 보조로 축소
- `Studio Mode` 토글(다크 전환): 제작 화면 전용(상단바 우측)
- `Atmosphere` 토글(Clean ↔ Filmic): 그레인/비네팅/스캔라인 같은 분위기 효과 On/Off

이 레이아웃/토글이 있으면 “라이트 기본”을 유지하면서도, 데모에서 필요할 때 “프로툴 모드”로 확 확 바꿀 수 있음.
