## 1) 병렬 작업 원칙 (팀이 동시에 움직이게 만드는 규칙)

1. **Contract First**: D1~D2에 최소 API/이벤트 스키마를 먼저 고정해서 FE/Worker가 서로 기다리지 않게 만든다.
2. **Job Schema Freeze**: Streams 토픽/메시지 구조/상태값은 D2에 합의 후, W3 동안 가급적 변경하지 않는다.
3. **금요일은 통합 버퍼**: 각 주차 D5는 신규 기능 금지(통합/E2E/버그픽스).
4. **서브시스템 단일 오너**: Worker는 구현 분담하되, 스키마/운영 개념은 전원 공통 이해.
5. **Fallback 준비**: WS는 푸시(실시간), HTTP는 폴링(대체) — 둘 다 있어야 데모 안정성이 올라간다.
