# 00. 전체 목표와 주차별 큰 그림

## 6주 프로젝트 목표
- **핵심 플로우를 끊김 없이 1회 완주**: 시나리오 → 씬/노드 → 이미지/영상 생성 → 확정 → 병합(concat) → 다운로드
- **전략**: 3주차에 “돌아가는 MVP”를 먼저 만들고, 4주차에 안정화/협업 준비, 5주차에 협업 기능, 6주차에 배포/데모

---

## 3주차(01/19~01/23) Done 정의 (MVP)
### 기능
- 로그인/회원가입(JWT)
- 프로젝트 생성
- 시나리오 생성(LLM) → 씬 자동 생성
- 씬 편집(Vue Flow): 노드 생성/상태 표시
- 이미지/영상 생성 Job 요청 → 비동기 처리 → 완료/실패 반영
- 영상 확정(confirm) → 타임라인 반영
- 병합(concat, 무오디오, 720p/H.264) → 다운로드 URL 제공

### 기술
- Redis Streams 기반 Job Queue
- Worker 3종: 이미지 / 영상 / FFmpeg 병합
- WebSocket: Job/노드/병합 상태를 FE에 푸시 (폴링 fallback 존재)

---

## 4주차(01/26~01/30) 목표: 안정화 + 협업 준비
- MVP 버그/리그레션 테스트
- 오브젝트 시트(일관성 관리) API + UI
- 멤버 초대/권한
- 업로드(presigned)
- Worker 모니터링/로깅, timeout/retry 정책 보강

---

## 5주차(02/02~02/06) 목표: 협업 MVP
### 포함(이번에 반드시)
- WebRTC **음성 통화** (최대 6명 기준)
- 채팅(WebSocket)
- Presence(누가 어느 화면/씬에서 작업 중인지)
- Cursor/Selection(커서 + 선택 노드 표시)
- Follow(선택적으로 다른 사람 화면/씬 따라가기)
- Soft Lock(충돌 예방용, 강제 잠금 아님)

### 제외(이번엔 안 함)
- 비디오(영상) 통화
- 화면 공유
- Yjs/CRDT로 “노드 그래프 동시 편집”

---

## 6주차(02/09~02/13) 목표: 통합 테스트 + 배포 + 데모
- 전체 플로우 통합 테스트(시나리오→편집→병합→협업)
- 성능 튜닝(병목 제거)
- 운영 배포(EC2/Docker)
- API 문서화(Swagger)
- 데모 시나리오/발표자료/데모영상
