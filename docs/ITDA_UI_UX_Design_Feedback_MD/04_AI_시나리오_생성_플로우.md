# 04. AI 시나리오 생성 4-Step 플로우 피드백

_작성일: 2026-01-26_


## 화면 범위
- `itda-presentation-v2.pdf`의 **AI 시나리오 생성** 4단계 UI (기본 정보 → 프롬프트 검토 → 줄거리 생성 → 씬 생성) 화면을 기준으로 작성했습니다.

이 플로우는 제품의 “첫 성공(첫 씬 생성)”을 만드는 핵심이기 때문에,
**정보 설계 + 마이크로카피 + 예외 처리**까지 촘촘히 잡으면 전환율이 크게 좋아질 구간입니다.

---

## 전체 구조 피드백 (4-step 공통)

### 1) Stepper는 “진행 상황 + 되돌리기 가능성”을 함께 보여야 함
- 현재처럼 1~4 단계가 상단에 노출되는 패턴은 좋습니다.
- 추가 추천:
  - 완료 단계에 체크 아이콘
  - 이전 단계로 돌아갈 때 “입력값 유지” 안내
  - 4단계 중 어디까지 자동 생성인지(=시간이 걸리는 구간) 표시

### 2) 우측 패널(overlay) 사용성
- 배경이 흐려지면서 패널이 뜨는 방식은 집중에 유리합니다.
- 다만 작업형 툴에서는 패널이 길어질 때 스크롤이 생기므로:
  - 패널 내부 스크롤과 페이지 스크롤이 충돌하지 않게 처리
  - 패널 상단에 **닫기(X)** 외에 `나가기`(명확한 카피)도 고려

### 3) “재생성”을 남용하게 만들지 않기
- 생성형 UX는 사용자가 “다시 생성”을 반복하면서 피로해지기 쉽습니다.
- 권장 구조:
  - 재생성 버튼은 Secondary
  - 그 대신 “내가 원하는 방향으로 고치는 입력”을 제공:
    - `더 밝게`, `더 짧게`, `갈등을 강화`, `반전 추가` 같은 “조정 프롬프트” 칩

### 4) 비용/시간/퀄리티 기대치 안내
- 최소 안내:
  - `예상 소요: 약 20~40초`
  - (유료 모델이면) `예상 크레딧 사용량`
- 이것만 있어도 “왜 안 끝나지?” 불만이 줄어듭니다.

---

## Step 1. 기본 정보 입력

### 목표
- AI가 좋은 시나리오를 만들도록 “필수 컨텍스트”를 빠르게 확보하는 단계

### 개선 포인트
1. **필수 입력 최소화**
   - 필수는 3개 내로 권장:  
     `장르` `분위기(톤)` `로그라인(한 줄 소개)`
   - 나머지는 “고급 설정”으로 숨기기

2. **프리셋/예시 제공**
   - 장르/분위기/배경은 사용자가 막히는 지점이라,
     클릭 한 번으로 채워지는 프리셋이 효과적입니다.
   - 예:
     - 장르: SF / 드라마 / 스릴러 …
     - 톤: 따뜻함 / 긴장 / 우울 …
     - 배경: 근미래 도시 / 사막 기지 …

3. **‘한 줄 소개’(로그라인) 입력 UX 강화**
   - placeholder만으로는 부족합니다.
   - 추천:
     - 아래에 예시 2개:  
       `예) 기억을 잃은 우주비행사가…`  
     - 글자 수 카운트
     - 입력이 어려운 사용자를 위한 “아이디어가 없어요” 버튼 → 랜덤 제안

---

## Step 2. 프롬프트 검토

### 목표
- 모델에 전달될 프롬프트를 사용자가 이해/수정할 수 있게 하는 단계

### 개선 포인트
1. **“프롬프트”를 그대로 노출할 때의 리스크**
   - 일반 사용자는 프롬프트 구조를 이해하기 어렵습니다.
   - 제안 UI:
     - 상단: “AI가 이렇게 이해했어요” 요약(자연어)
     - 하단: 고급 옵션으로 “프롬프트 원문 보기” 토글

2. **편집 모드 제공**
   - 텍스트 에디터에:
     - 자동 포맷(불릿/문단)
     - 강조(장르/톤/주인공) 하이라이트
   - 수정 후 버튼:
     - `이대로 줄거리 생성`(primary)
     - `다시 생성`(secondary)

3. **‘다시 생성’ 대신 ‘조정’ 중심 CTA**
   - 프롬프트 하단에 조정 칩:
     - `더 감성적으로` `대사를 줄이기` `반전 추가` `러닝타임 30초 기준`
   - 사용자는 “재생성”보다 “조정”을 선호하게 됩니다.

---

## Step 3. 줄거리 생성

### 목표
- 전체 서사를 만들고, 씬 생성으로 넘어갈 “뼈대”를 확정하는 단계

### 개선 포인트
1. **줄거리 결과를 ‘구조화’해서 보여주기**
   - 긴 텍스트 덩어리는 읽기 어렵습니다.
   - 추천 포맷:
     - 로그라인(1문장)
     - 등장인물(2~3명)
     - 3막 구조(시작/전개/결말) 또는 비트(Beat) 리스트

2. **편집의 최소 단위 제공**
   - 전체 텍스트 편집도 좋지만,
     사용자에게는 “부분 편집”이 더 쉽습니다.
   - 예: 각 비트 옆에 `수정` 버튼

3. **“이 줄거리로 씬 생성” CTA를 압도적으로 명확하게**
   - 이 단계의 목적은 ‘다음 단계’로 넘기는 것이므로,
     Primary CTA는 반드시:
     - `씬 생성하기` 또는 `씬 생성 단계로 이동`

---

## Step 4. 씬 생성

### 목표
- 줄거리에서 ‘실제 작업 단위(씬)’를 뽑아 프로젝트에 적용하는 단계

### 개선 포인트 (리스트 UX)
1. **씬 카드의 정보 구성**
   - 카드당 최소:
     - 씬 제목
     - 1~2줄 요약
     - 예상 길이(초) 또는 샷 수(대략)
     - 감정 톤(태그)
   - 그리고 액션:
     - `편집` `삭제` `재생성`(… 메뉴로)

2. **일괄 적용(Apply) 버튼의 조건 명확화**
   - `프로젝트에 적용(5개 씬)` 같은 버튼은 좋습니다.
   - 다만 “선택된 씬 수”가 변하면 버튼 레이블이 동적으로 바뀌어야 합니다.
   - 선택 UX:
     - 전체 선택/해제
     - 씬별 체크박스

3. **적용 후 다음 행동 자동 제안**
   - 적용이 끝나면:
     - `노드 캔버스에서 마스터 이미지 생성하기` (primary)
     - `씬 순서 조정` (secondary)
   - 즉시 다음 단계로 안내하면 “끊김 없는 워크플로우”가 완성됩니다.

---

## 예외 처리(꼭 넣어야 하는 것)
- 생성 실패:
  - `네트워크 오류로 생성에 실패했어요. 다시 시도할까요?`
  - 실패한 단계에서 다시 시작(입력값 유지)
- 생성 중 취소:
  - `생성을 중단하면 현재 결과는 저장되지 않을 수 있어요.`
- 버전:
  - 줄거리/씬 생성 결과를 “v1/v2”로 보관하고 비교 가능하면 사용자가 안심합니다.

---

## 체크리스트
- [ ] Stepper 완료/진행/되돌리기 상태 명확화
- [ ] 프롬프트 원문은 “고급”으로 숨기고 요약을 먼저 제공
- [ ] 재생성보다 “조정” 인터랙션(칩/슬라이더) 강화
- [ ] 씬 카드 구조화 + 선택 기반 Apply
- [ ] Apply 이후 다음 단계 CTA 자동 안내
