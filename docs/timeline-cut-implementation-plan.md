# 타임라인 컷(그리드) UX + 마스터 정지 프레임 프롬프트 개선 구현 계획

## 0. 맥락
현재 그리드 모드에는 **샷 변주(Shot Variations)**와 **스토리 비트(Story Beats)**가 있으며,
사용자는 “영상처럼 시간의 흐름이 있는 그리드”를 원함.  
하지만 “스토리 비트”라는 용어는 직관성이 낮고, 마스터 이미지에는 **정지된 한 프레임**이 필요함에도
현재 프롬프트 흐름에는 이를 강제하는 로직이 부족함.

또한 `prompt_guide.txt`의 핵심 원칙은 **키워드 나열이 아닌 장면 서술**이며,
**Sequential art/storyboard**는 패널별로 시간 흐름을 다루는 것이 자연스러움.

---

## 1. 목표
1) **마스터 이미지**는 항상 “정지된 establishing frame” 기반으로 프롬프트가 생성/렌더링되도록 한다.  
2) **그리드 모드의 시간 흐름**은 “스토리 비트” 대신  
   **타임라인 컷(키프레임)** 개념으로 UX를 재정의한다.  
3) 사용자가 “영상의 2초 간격 프레임을 모아 본다”는 느낌을 직관적으로 이해하도록 한다.

---

## 2. 용어 정리 (UI 기준)
- **샷 변주(Shot Variations)**: 동일 순간, 프레이밍만 다른 컷들의 그리드
- **타임라인 컷(Timeline Cuts)**: 영상 흐름을 2초(기본) 간격으로 나눈 정지 프레임 그리드

> 기존 `STORY_BEATS`는 UI에서 “타임라인 컷”으로 리네이밍하고 의미를 변경한다  
> (백엔드 파라미터 이름은 유지 또는 변경 옵션 참고)

---

## 3. UX 설계 (그리드 타임라인 컷)

### 3.1 모드 선택
- 모드 토글:
  - “샷 변주”
  - “타임라인 컷”
- 타임라인 컷 모드 선택 시 다음 UI 노출

### 3.2 레이아웃 = 컷 개수
- 레이아웃 선택이 곧 컷 개수 (2x2=4컷, 3x2=6컷 등)

### 3.3 타임라인 라벨
- 기본 간격: 2초
- 각 패널 라벨은 **시간 구간**으로 표시  
  예: 4컷(2x2) → `0–2s`, `2–4s`, `4–6s`, `6–8s`
- 사용자는 “이 구간을 대표하는 정지 프레임”을 묘사

> 구간 라벨 방식이 “영상 8초 내 4컷” 느낌을 가장 직관적으로 전달함

### 3.4 입력 UX
- **공통 서술 프롬프트** (전체 상황/배경/인물 공통)
  - 기본값: **마스터 이미지에서 사용한 서술 프롬프트를 자동 복사**
  - 사용자가 수정 가능
- **컷별 입력** (1~2문장 권장)
  - 기본은 숨김 상태
  - AI가 자동 생성한 컷 내용을 확인/편집하는 영역으로 사용
- **연속성 규칙** (공통 요소 고정, 선택)
- **고급 옵션(접기)**
  - 컷별 상세 지시(샷 타입/표정/감정 키워드)
  - 기본은 숨김 (대부분 사용하지 않을 것으로 예상됨)

### 3.5 보조 UX
- “타임라인 컷 자동 생성” 버튼
  - 서술 프롬프트를 기반으로 컷별 내용을 AI가 자동 분할/생성
- “컷 편집하기” 버튼
  - 숨겨진 컷 입력 영역을 펼치고 하이라이트 + 스크롤/포커스 처리
- 컷 입력 “이전 컷 복사 / 연장” 버튼

---

## 4. 프롬프트 정책 (핵심 룰)

### 4.1 마스터 이미지 (정지 프레임)
**목표**: Establishing still frame 강제

- 규칙 문구 (엔진 프롬프트 지침에 포함):
  - “opening establishing still frame” (시작점/오프닝 컷의 의미를 부여)
  - “single still frame”
  - “no temporal progression”
  - “no before/after, no passing-by”
  - “wide establishing shot, locked-off camera”
- 문장 길이: 1–2문장 (간결)
- **원문에 없는 요소 추가 금지**
- `prompt_guide.txt` 원칙 적용:
  - “Describe the scene, don’t list keywords.”

### 4.2 타임라인 컷 (그리드)
**목표**: 2초 구간의 정지 프레임 시퀀스

- 각 컷은 **해당 시간 구간의 한 프레임**
- 컷 간 연속성(인물/장소/조명/소품) 유지
- “키워드 나열 금지, 장면 서술 중심”
- 컷별 문장 길이 1–2문장
- `prompt_guide.txt` 원칙 적용:
  - “Sequential art/storyboard는 패널별로 명확한 장면 서술.”

---

## 5. 데이터/로직 구조 결정 (확정)

### 5.1 gridMode 결정
- 기존 `gridMode = STORY_BEATS` 유지
- UI 라벨만 “타임라인 컷”으로 변경
- beats 배열을 “컷별 프레임 설명”으로 사용
- continuityRules 유지

**이유:** API/백엔드 변경 최소화, 구현 범위 축소

### 5.2 시간 라벨 결정
- **구간 표시 방식** 사용 (예: 0–2s, 2–4s, 4–6s, 6–8s)

**이유:** “영상의 한 구간을 대표하는 프레임”이라는 의미가 가장 직관적

### 5.3 고급 옵션 범위 결정
- 컷별 **샷 타입**
- 컷별 **표정/감정 키워드**
- 카메라 움직임은 **정지 프레임 개념과 충돌**하므로 제외

**이유:** 실사용 빈도가 낮은 옵션은 최소화하고, 컷 디테일 조정에 필요한 핵심만 제공

---

## 6. 구현 단계(프론트 중심)

1) **그리드 모드 UI 라벨 변경**
   - “스토리 비트” → “타임라인 컷”
2) **타임라인 컷 입력 UI 추가**
   - 컷별 타임 구간 라벨 표시
   - 기본 간격 2초 (옵션 UI는 추후 확장)
3) **서술 프롬프트 연동**
   - 마스터 서술 프롬프트 자동 복사 (초기값)
   - 사용자가 수정 가능
4) **타임라인 컷 자동 생성 UX**
   - “AI로 다듬기” 클릭 시 컷별 내용 자동 생성
   - 서술 프롬프트 변경만으로는 자동 재생성되지 않음
5) **컷 편집 UX**
   - “컷 편집하기”로 숨겨진 컷 입력 영역 펼치기 + 하이라이트
6) **고급 옵션 UI**
   - 컷별 상세 지시 입력을 접기 영역으로 제공

---

## 7. 구현 단계(프롬프트/백엔드)

1) **마스터 프롬프트 지침 강화**
   - 프롬프트 생성/렌더링 단계에 “still frame” 지침 추가
2) **타임라인 컷 프롬프트 렌더링 규칙**
   - “각 비트=시간 구간의 정지 프레임”을 명시
   - 연속성 규칙을 반드시 포함
3) **컷 자동 생성 엔드포인트(또는 내부 로직)**
   - 입력: 서술 프롬프트 + 컷 개수(레이아웃 기반)
   - 출력: 컷별 설명 리스트
   - 호출 시점: **“AI로 다듬기” 버튼 클릭 시에만 재생성**
3) **prompt_guide.txt 반영**
   - “타임라인 컷 = sequential still frames” 가이드 추가

---

## 8. 테스트/검증 시나리오

### 8.1 마스터
- 씬 설명이 서사적이어도 결과 프롬프트가 정지 프레임 기준인지 확인
- “지나가며/찰나/이후” 같은 시간 표현이 출력되지 않는지 확인

### 8.2 타임라인 컷
- 2x2 레이아웃 → 0–2s, 2–4s, 4–6s, 6–8s 표시 확인
- 컷별 입력이 잘 저장되고 프롬프트에 포함되는지 확인
- 연속성 규칙이 최종 프롬프트에 포함되는지 확인

---

## 9. 결정 사항 (확정)
- `gridMode`는 **STORY_BEATS 유지**, UI 라벨만 “타임라인 컷”
- 시간 라벨은 **구간 방식(0–2s)** 적용
- 고급 옵션은 **샷 타입 + 표정/감정 키워드**만 제공

---

## 10. 결론
- 마스터는 “정지 프레임 establishing shot” 강제
- 그리드는 “타임라인 컷”으로 재정의
- 기존 프롬프트 구조는 유지하되, **의미와 UX를 명확하게 분리**
